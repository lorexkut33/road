## 🌐 Сеть

| Команда | Описание |
|--------|----------|
| `ip a` | Сетевые интерфейсы и IP-адреса |
| `ip r` | Таблица маршрутизации |
| `ping host` | Проверить доступность хоста (протокол ICMP, 3-й уровень OSI) |
| `curl url` | HTTP-запрос к веб-серверу (7-й уровень OSI) |
| `curl -I url` | Отправить запрос и вывести только HTTP-заголовки ответа (коды ответа 200, 404, куки, сервер) |
| `wget url` | Скачать файл по URL |
| `ss -tulnp` | Открытые порты и сокеты (TCP/UDP) |
| `sudo ss -tlnp` | Показать только TCP (`-t`), слушающие порты (`-l`), цифрами (`-n`) с именами процессов и PID (`-p`) |
| `sudo ss -tlnp \| grep :22` | Отфильтровать вывод портов, оставив только информацию по 22-му порту (SSH) |
| `netstat -tulnp` | То же (устаревший вариант) |
| `nslookup domain` / `nslookup [domain]` | Отправляет запросы к DNS-серверам для преобразования символьных доменов в IP-адреса |
| `traceroute host` | Трассировка маршрута до целевого хоста |
| `hostname -I` | Выводит исключительно IP-адреса текущего Linux-окружения (внутри WSL) |
| `tracepath -n [domain]` | Выполнение трассировки маршрута без разрешения имён. Флаг `-n` отображает только целевые IP-адреса хопов |
| `traceroute -n [domain]` | Выполнение трассировки маршрута пакета, отображая цепочку маршрутизаторов (хопов — прыжков), через которые проходят пакеты до цели. Флаг `-n` отображает не доменные названия, а целевые IP-адреса |
| `nc -zv [host] [port]` | Сканирует доступность конкретного TCP или UDP порта на узле. Флаг `-z` (zero-I/O) тестирует подключение без передачи данных, а `-v` (verbose) включает подробный вывод статуса |
| `nc -l [port]` | Запуск утилиты в режиме прослушивания. Флаг `-l` (listening) слушает определенный порт для создания временного сокета |
| `nc -w 1 [port]` | Отправляет данные на определенный порт, который находится в режиме (listening). Флаг `-w 1` задает таймаут ожидания в 1 секунду |
| `arp -n` / `ip neighbor` | Просмотр ARP-таблицы (сопоставление IP-адресов узлов в локальной сети с их физическими MAC-адресами) |
| `sudo nmap -sV [target]` | Сканирование портов целевого хоста с определением версий запущенных служб (`-sV`). При жесткой защите выдает статус `tcpwrapped` |
| `sudo tcpdump -i eth0 -c 5` | Перехват трафика на интерфейсе `eth0` (`-i`). Поймать ровно 5 пакетов (`-c 5`) и завершить работу |
| `sudo tcpdump -i eth0 dst host [IP]` | Перехват исходящего трафика на интерфейсе `eth0`, где получателем (`dst host`) является указанный IP (например, сервер Telegram) |
| `sudo tcpdump -i eth0 port [port] -w dump.pcap` | Запись всего трафика с конкретного порта в файл `dump.pcap` (`-w`) для последующего анализа в Wireshark |
| `tcpdump -r dump.pcap` | Прочитать и вывести в терминал содержимое ранее записанного `.pcap` файла (`-r`) |
| `sudo iptables -A INPUT -p tcp -s [IP] --dport 22 -j ACCEPT` | Добавить правило в файрвол: разрешить входящий (`INPUT`) TCP-трафик со специфичного IP на 22-й порт |
| `sudo iptables -A INPUT -p tcp --dport 22 -j DROP` | Добавить правило в файрвол: молча сбрасывать (`DROP`) все остальные входящие TCP-пакеты на 22-й порт |
| `ssh user@host` | Подключиться к удаленному серверу по протоколу SSH (порт 22) |
| `ssh -D 8080 -p 443 user@host` | Создать динамический SSH-туннель на локальном порту 8080, инкапсулируя запрещенный трафик в разрешенный порт 443 |
| `scp file user@host:/path` | Безопасное копирование файла на удаленный хост через SSH-соединение |

## 📜 Протоколы (Теория и Реальный DevOps-контекст)

| Протокол | Уровень OSI | Как работает (На пальцах) | Реальный кейс в Docker / на работе |
| :--- | :---: | :--- | :--- |
| **TCP**<br>*(Transmission Control Protocol)* | **L4**<br>Транспортный | **Надежный курьер.** Устанавливает связь через трёхэтапное рукопожатие (`SYN` -> `SYN-ACK` -> `ACK`). Проверяет доставку каждого байта. Если кусок потерялся — переотправляет его. | Используется там, где нельзя терять данные: подключение бэкенда (Flask/FastAPI) к базам данных (PostgreSQL/MySQL), трафик веб-серверов (Nginx). |
| **UDP**<br>*(User Datagram Protocol)* | **L4**<br>Транспортный | **Пулемётчик.** Не здоровается, не проверяет доставку. Просто швыряет пакеты в сеть на бешеной скорости. Потеря пакетов не останавливает поток. | Сбор системных логов и метрик с сотен серверов (Fluentbit -> Elasticsearch, Prometheus/StatsD), созвоны и стримы в Telegram/Discord, DNS-запросы. |
| **ICMP**<br>*(Internet Control Message Protocol)* | **L3**<br>Сетевой | **Сетевой пульс.** Не передает файлы или сайты. Служит для обмена служебными сообщениями об ошибках и проверки доступности узлов. | На нём работает утилита `ping` (системы мониторинга Grafana/Zabbix раз в 10 секунд проверяют, жив ли сервер базы данных) и утилита `traceroute`. |
| **HTTP**<br>*(HyperText Transfer Protocol)* | **L7**<br>Прикладной | **Язык веба.** Работает поверх TCP. Чистый текст, командный интерфейс взаимодействия браузера и сервера (`GET`, `POST`, `DELETE`). Возвращает цифровые коды статуса. | Настройка балансировщика Nginx. Ошибка `200` — всё ОК, `404` — нет файла, `502 Bad Gateway` — Nginx жив, но твой Docker-контейнер с Python завис или упал. |
| **TLS / SSL**<br>*(Transport Layer Security)* | **L6**<br>Представительский | **Сейф для трафика.** Шифрует открытый текст протокола HTTP с помощью математических ключей, превращая его в безопасный HTTPS. Защищает от перехвата пакетов. | Генерация SSL-сертификатов через *Let's Encrypt* (файлы `.crt` и `.key`) и прописывание путей к ним в конфиге Nginx для защиты паролей пользователей. |
| **DNS**<br>*(Domain Name System)* | **L7**<br>Прикладной | **Телефонная книга интернета.** Переводит человеческие имена сайтов и контейнеров (`api.google.com`) в цифровые IP-адреса (`1.2.3.4`). | Локальный DNS внутри Docker Compose. Микросервисы общаются по именам контейнеров (`auth-service`). Главный виновник 70% сетевых сбоев (из-за кэша TTL). |
| **SSH**<br>*(Secure Shell)* | **L7**<br>Прикладной | **Пульт управления.** Протокол для безопасного удаленного администрирования серверов Linux через терминал. Работает по TCP на стандартном **22 порту**. | Подключение к серверам в облаке (Яндекс/VK Cloud). DevOps обязан отключать авторизацию по паролям и настраивать доступ строго по приватным SSH-ключам. |
| **ARP**<br>*(Address Resolution Protocol)* | **L2**<br>Канальный | **Связист-переводчик.** Связывает виртуальный IP-адрес (L3) с реальным, вшитым в сетевую карту физическим MAC-адресом (L2) внутри одной локальной сети. | Ноутбук хочет скинуть Docker-образ на тестовый сервер в офисе. Он кричит в сеть ARP-запрос: *«У кого IP 192.168.1.100? Дайте ваш MAC!»*, запоминает его и шлет данные в провод. |

## 📝 Bash — полезные конструкции

```bash
# Переменные
NAME="world"
echo "Hello, $NAME"

# Условие
if [ -f file.txt ]; then
  echo "Файл существует"
fi

# Цикл по файлам
for f in *.log; do
  echo "$f"
done

# Цикл по числам
for i in {1..5}; do
  echo "Итерация $i"
done

# Функция
hello() {
  echo "Hello, $1"
}
hello "Artём"
```
